# 自动化验证方案

## 1. 单元测试

当前已补最小可执行单元测试：

- `ApplicationCommandServiceTest`
  - 候补确认接受：验证 `WAITLIST_PENDING_CONFIRM -> RESERVED`
  - 候补确认拒绝：验证关闭和释放配额调用
- `DomesticReviewServiceTest`
  - 认领：验证 `SUBMITTED -> DOMESTIC_REVIEWING`
  - 审核通过：验证 `DOMESTIC_REVIEWING -> SCHOOL_REVIEWING`
- `SchoolReviewServiceTest`
  - 学校审核录取：验证 `SCHOOL_REVIEWING -> RESERVED`
  - 学校审核候补：验证 `SCHOOL_REVIEWING -> WAITLISTED` 且生成候补记录

实现方式：

- 使用 Mockito + 现有 `spring-boot-starter-test`
- 不新增外部测试依赖，避免离线环境拉包失败
- 重点验证：
  - `applications.current_status`
  - `waitlist_records`
  - `application_status_histories`
  - `audit_logs`
  - 配额服务调用边界

## 2. 集成测试

继续沿用并增强：

- [scripts/verify-min-api-flow.ps1](./scripts/verify-min-api-flow.ps1)

覆盖主链路：

1. 登录 -> 创建草稿 -> 提交申请
2. 国内审核 -> 补件 -> 再提交 -> 通过
3. 学校审核 -> 候补 / 录取 / 调剂
4. 候补确认 / 超时关闭

建议执行方式：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-min-api-flow.ps1
```

## 3. 接口回归测试

当前建议分两层：

- Mockito 单元测试：守住服务层状态机和日志回归
- PowerShell 集成脚本：守住 HTTP 链路、权限、数据库结果

回归关注点：

- 状态机是否按 PRD 迁移
- 角色权限是否正确拦截
- `audit_logs` 和 `application_status_histories` 是否完整
- 学校/专业配额是否正确扣减和释放
