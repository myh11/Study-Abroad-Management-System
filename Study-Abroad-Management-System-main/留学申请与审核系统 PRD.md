## 2. 产品背景与建设目标

### 2.1 产品背景

本系统用于支持“去哪学”教育机构与“澳洲高校联盟”合作的高中生赴澳留学申请业务，实现：

+ 代理专员代学生提交申请
+ 国内审查员审核基础资质
+ 学校专员审核专业适配度并进行占位
+ 系统管理申请状态、名额与日志

原始 PRD 仅给出了基础业务框架，包括学生申请、国内审核、学校审核、分配结果等，但未明确状态流转、评分细则、异常处理、权限粒度及数据约束，无法直接支撑开发。

### 2.2 建设目标

系统建设目标包括：

1. 实现留学申请业务线上化
2. 建立统一、可执行的审核标准
3. 实现学校总名额与专业名额双重控制
4. 支持撤销、补件、候补、调剂等业务场景
5. 确保数据可追踪、规则可配置、操作可审计
6. 降低审核口径不一致带来的风险
7. 支持后续扩展更多学校、专业和智能推荐能力

### 2.3 非目标范围

本期不覆盖：

+ 最终正式录取结果发放
+ 签证办理
+ 缴费与合同签署
+ 对接真实学籍官方数据库
+ 真伪司法鉴定类 OCR / 图像鉴伪系统

## 4. 角色定义与权限模型

### 4.1 角色定义

#### 4.1.1 代理专员

负责为学生创建申请、上传材料、提交申请、查看申请状态、在规则允许时撤销申请、接收调剂建议并决定是否重新申请。

#### 4.1.2 国内审查员

负责对申请进行基础资质审核，包括材料完整性、成绩基础门槛、身份一致性、真实性风险审核。

#### 4.1.3 学校专员

按学校划分，仅处理本校申请，负责学校审核、专业审核、占位、候补和调剂建议。

#### 4.1.4 系统管理员

负责维护学校、专业、配额、分数线、批次、用户账号、日志查看与异常处理。

## 5. 学校、专业与招生批次模型

这是本版新增补齐内容之一。若没有“招生批次”概念，系统多轮使用后，申请、名额、候补将混杂，导致后续统计和业务判断混乱。

### 5.1 招生批次定义

系统中的所有申请、配额、候补、审核都必须绑定一个招生批次，例如：

+ 2026春季批次
+ 2026秋季批次
+ 2027春季批次

### 5.2 批次字段要求

每条申请必须包含：

+ 批次编号
+ 批次名称
+ 批次开始时间
+ 批次结束时间
+ 批次状态（未开始 / 进行中 / 已结束）

### 5.3 批次约束

+ 学校总名额按批次管理
+ 专业名额按批次管理
+ 候补名单按批次独立排序
+ 同一学生可以跨批次重新申请，但需遵守当批次规则

### 5.4 学校配置

系统初始支持：

+ 澳洲国立大学（ANU）
+ 悉尼大学（USYD）
+ 新南威尔士大学（UNSW）

## 6. 产品核心业务规则

### 6.1 单申请规则

同一学生在同一时间只能存在一条有效中的申请。

有效中的申请状态包括：

+ 已提交
+ 国内审核中
+ 国内补充材料
+ 学校审核中
+ 候补中
+ 候补补位待确认

### 6.2 不可修改规则

申请一经提交，不允许直接修改以下字段：

+ 学生姓名
+ 当前学校
+ 目标学校
+ 目标专业
+ 原始成绩结构化结果

如需变更，只能通过：

+ 撤销后新建申请
+ 或在“建议调剂”场景下生成派生申请

### 6.3 撤销规则

允许撤销的状态：

+ 已提交
+ 学校审核中
+ 候补中

不允许撤销的状态：

+ 占位成功
+ 国内审核不通过
+ 学校不通过
+ 已关闭

### 6.4 重复申请规则

学生撤销某学校申请后，不允许在同一批次内再次申请该学校。

### 6.5 调剂规则

调剂不是直接修改原申请，而是：

1. 学校给出“建议调剂”
2. 代理确认是否接受
3. 系统生成新申请，继承原始材料并记录来源申请编号

### 6.6 候补规则

若学生满足学校与专业要求，但专业或学校配额暂满，则进入候补中状态。

### 6.7 规则快照机制

这是本版新增补齐内容之一，用于避免后续配置变更影响历史申请。

每条申请在正式提交时，系统必须保存一份“规则快照”，包括：

+ 当时所属批次
+ 学校最低门槛
+ 专业最低门槛
+ 占位线
+ 候补线
+ 配额规则版本
+ 调剂规则版本
+ 候补排序规则版本

这样即使管理员后续调整分数线或配额，已提交申请仍按提交时的规则审核。

## 7. 中文状态字典

这是你要求补齐的第一项。下面所有状态均使用中文显示名称。

### 7.1 状态定义

#### 申请草稿

代理正在填写资料，尚未正式提交。
特征：仅代理和管理员可见，不参与审核。

#### 已提交

申请已由代理正式提交，等待进入国内审核。
特征：申请已锁定，不可直接编辑。

#### 国内审核中

国内审查员已接收申请并开始审核。
特征：国内审核过程进行中。

#### 国内审核通过

申请通过国内资质审核，待进入学校审核。
特征：具备学校审核资格。
实现口径：该状态作为业务里程碑，系统自动流转到“学校审核中”，不作为持久停留状态。

#### 国内补充材料

国内审核认为当前材料不充分，需要代理补件。
特征：允许补充附件和说明，但不允许改申请意图。

#### 国内审核不通过

申请未达到国内资质标准，流程终止。
特征：终止性业务状态。

#### 学校审核中

学校专员正在对该申请进行学校与专业审核。
特征：可进行评分、占位、候补、调剂建议、拒绝。

#### 占位成功

学校已为该学生分配专业名额，申请占位完成。
特征：配额已扣减。

#### 建议调剂

学校不接受当前专业申请，但给出调剂建议。
特征：原申请不再继续占位，代理可选择是否接受建议并生成新申请。

#### 候补中

学生满足要求，但暂时无名额，进入候补队列。
特征：等待释放名额或补位。

#### 学校不通过

学校审核拒绝该申请。
特征：学校阶段终止。

#### 已撤销

代理或管理员在允许条件下主动撤销申请。
特征：该申请终止。

#### 已关闭

流程归档状态。
特征：用于业务结束后的统一终态管理。

## 10. 国内资质审核设计

### 10.1 审核目标

筛掉明显不符合条件或材料存在较大风险的申请，避免无效申请进入学校审核环节。

### 10.2 审核步骤

#### 步骤一：材料完整性检查

检查是否已提交所有必要字段与附件。

#### 步骤二：身份一致性检查

比对：

+ 申请姓名与成绩单姓名
+ 申请学校与成绩单学校
+ 学生信息是否一致

#### 步骤三：成绩基础线检查

统一基础门槛：

+ 平均分 ≥ 70
+ 核心课程平均分 ≥ 65
+ 不及格科目数 ≤ 1

#### 步骤四：真实性风险审核

检查：

+ 文件是否有效
+ 是否包含关键字段
+ 是否存在疑似印章区域
+ 分数是否异常
+ 总评与单科是否逻辑一致
+ 学期顺序是否合理

#### 步骤五：规范性检查

检查扫描件清晰度、自荐材料完整度、文件格式规范性。

### 10.3 国内审核结论

可输出：

+ 国内审核通过
+ 国内补充材料
+ 国内审核不通过

### 10.4 补件边界

国内补充材料只允许：

+ 补传附件
+ 替换模糊扫描件
+ 补充说明文本

不允许修改：

+ 学生姓名
+ 学校
+ 目标学校
+ 目标专业
+ 原始成绩事实

## 11. 成绩单真实性风险审核

### 11.1 审核定位

系统只进行“真实性风险审核”，不宣称做出法律意义的真伪认证。

### 11.2 机器初筛

自动检查：

+ 文件格式
+ 文件是否损坏
+ 关键字段是否齐全
+ 分数范围是否合法
+ 总分与单科逻辑是否一致
+ 是否存在疑似印章区域
+ 清晰度是否可读

### 11.3 人工复核

国内审查员检查：

+ 排版是否合理
+ 是否有明显拼接、涂改痕迹
+ 学校名称、学期、姓名是否一致
+ 印章位置和形式是否合理

### 11.4 风险等级

+ A级：低风险
+ B级：一般风险
+ C级：中风险，需人工重点复核
+ D级：高风险，建议拒绝

------

## 12. 学校审核与专业分配设计

### 12.1 审核目标

判断学生是否满足目标学校和专业要求，并决定是否占位、候补、调剂或拒绝。

### 12.2 审核顺序

1. 是否满足学校最低要求
2. 是否满足申请专业最低要求
3. 学校配额是否足够
4. 专业配额是否足够
5. 综合评分是否达到占位线
6. 若不满足，是否存在合适调剂专业
7. 若无空位但条件满足，是否进入候补

### 12.3 学校评分模型

总分 100 分：

+ 学业成绩：70 分
+ 材料质量：20 分
+ 专业匹配度：10 分

#### 学业成绩（70）

+ 平均分：40
+ 关键课程：30

#### 材料质量（20）

+ 自荐材料质量：10
+ 材料完整与规范：10

#### 专业匹配度（10）

+ 核心学科匹配：4
+ 学科背景匹配：3
+ 申请动机与专业一致性：3

### 12.4 自荐材料评分细化

为了降低主观差异，自荐材料质量按以下维度评分：

+ 字数达标：2
+ 内容结构完整：2
+ 申请动机明确：2
+ 专业理解清晰：2
+ 表达规范：2

### 12.5 学校审核结果

+ 占位成功
+ 建议调剂
+ 候补中
+ 学校不通过

------

## 13. 调剂机制设计

### 13.1 调剂原则

1. 优先同校调剂
2. 优先相近专业
3. 优先仍有配额专业
4. 优先综合评分高匹配专业

### 13.2 调剂流程

1. 学校专员生成调剂建议
2. 系统展示建议给代理专员
3. 代理确认是否接受
4. 若接受，系统生成新申请并保留来源关系
5. 新申请按新规则进入流程

### 13.3 调剂与撤销边界

+ 调剂不等于撤销后重申
+ 调剂属于业务链路内派生申请
+ 不受“撤销后不得再申请同校”限制

------

## 14. 候补机制与时效规则

这是你要求补齐的第四项。之前仅定义了候补排序，没有闭环到“多久确认、超时怎么办”。

### 14.1 候补适用条件

学生满足学校和专业基本要求，但当前无可用名额。

### 14.2 候补排序规则

按以下顺序排序：

1. 综合评分高者优先
2. 国内审核通过时间早者优先
3. 关键科目分数高者优先
4. 申请提交时间早者优先

### 14.3 候补时效规则

+ 候补转占位后，代理需在 **48 小时** 内确认
+ 若 48 小时未确认，视为放弃
+ 系统自动将机会转给下一位候补
+ 候补资格截至所属招生批次结束日
+ 批次结束后仍未转正的候补自动关闭

### 14.4 候补失效条件

+ 代理主动撤销
+ 超时未确认
+ 学校专员判定不再适用
+ 批次结束

------

## 15. 名额控制与并发处理

### 15.1 控制原则

占位时必须同时满足：

+ 学校剩余名额 > 0
+ 专业剩余名额 > 0

### 15.2 并发风险

若多人同时抢最后一个名额，可能导致配额超发。

### 15.3 处理方案

占位必须采用事务机制，步骤如下：

1. 锁定申请记录
2. 锁定学校配额记录
3. 锁定专业配额记录
4. 再次校验剩余配额
5. 更新学校已用名额
6. 更新专业已用名额
7. 更新申请状态为占位成功
8. 写入日志
9. 提交事务

任一步失败必须整体回滚。

### 15.4 名额释放规则

以下场景需释放配额：

+ 管理员纠错取消占位
+ 系统异常回滚
+ 候补转正超时放弃
+ 业务清理关闭占位

## 18. 异常处理

### 18.1 表单异常

+ 文件上传失败：允许重试，不丢失表单
+ 字段校验失败：即时提示
+ 学校专业不匹配：禁止提交

### 18.2 流程异常

+ 重复点击提交：接口幂等保护
+ 审核中断：保持原状态并记录日志
+ 审核时申请状态已变化：拒绝提交并提示刷新

### 18.3 数据异常

+ 专业配额已满仍尝试占位：拒绝占位
+ 学校总名额与专业名额不一致：阻止配置发布
+ 历史申请数据缺失：阻止继续流程并上报管理员

## 21. 典型业务场景

### 21.1 直接占位成功

学生申请悉尼大学软件工程，满足学校与专业门槛，评分达到占位线，学校与专业均有剩余名额，结果为占位成功。

### 21.2 国内补件

学生提交的成绩单模糊，国内审查员要求补件，状态转为国内补充材料，代理补传清晰扫描件后重新提交。

### 21.3 建议调剂

学生申请澳洲国立大学计算机，未满足该专业要求，但符合国际关系专业条件，学校给出建议调剂，代理确认后生成新申请。

### 21.4 候补转正

学生初审、校审均通过，但专业满额，进入候补中；后续因已有占位学生放弃，系统按排序补位，代理在 48 小时内确认后转为占位成功。

### 21.5 学校不通过

学生通过国内审核，但不满足目标学校与其他可调剂专业要求，学校不通过，流程结束。
