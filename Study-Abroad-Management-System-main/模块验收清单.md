# 模块验收清单

文档优先级：`PRD > 后端接口文档 v4 > 一页式项目开工冻结页 > 开发 ownership 表 > 前端页面与路由清单 > 个人理解`

## 一、统一验收前置条件

- 必须使用固定测试账号登录。
- 首次登录必须先执行 `POST /api/auth/change-password`。
- 必须使用固定联调数据：
  - `124` `127` `128` `129` `130` `132` `137` `138` `142` `144`
- 必须只调用《后端接口文档 v4》已实现接口。
- 禁止手工改库造“通过了但流程没走”的假结果。
- 验收时必须同时看三类结果：
  - 页面表现
  - 接口返回
  - 数据库记录

## 二、A 模块验收（代理端）

### 1. 页面范围

- `ApplicationCreatePage`
- `ApplicationListPage`
- `ApplicationDetailPage`

### 2. 必须完成

- 能登录并在首次登录时完成改密
- 能上传成绩单
- 能创建申请草稿
- 能查看“我的申请”列表
- 能查看申请详情
- 能在 `DOMESTIC_SUPPLEMENT` 状态下提交补件
- 能提交申请
- 能对允许撤销的申请发起撤销
- 能对 `WAITLIST_PENDING_CONFIRM` 申请执行候补确认
- 能对 `ADJUSTMENT_SUGGESTED` 或调剂草稿执行接受/拒绝调剂

### 3. 必须真实联调的接口

- `POST /api/auth/login`
- `POST /api/auth/change-password`
- `GET /api/auth/me`
- `POST /api/files/transcripts`
- `POST /api/files/attachments`
- `POST /api/applications`
- `GET /api/applications/my`
- `GET /api/applications/{id}`
- `POST /api/applications/{id}/supplement`
- `POST /api/applications/{id}/submit`
- `POST /api/applications/{id}/cancel`
- `POST /api/applications/{id}/waitlist-confirm`
- `POST /api/applications/{id}/accept-adjustment`
- `POST /api/applications/{id}/reject-adjustment`

### 4. 必须通过的固定场景

- `124`：补件上传后重新提交成功
- `128`：候补确认接受或拒绝成功
- `130` 或 `144`：拒绝调剂成功
- `132`：撤销终态展示正确，且不可再申同批次同校规则可验证
- 新建草稿：创建成功后能在“我的申请”里查到

### 5. 数据库验收点

- 补件后，`transcripts.file_id` 已更新
- 提交后，`applications.current_status` 合法变化
- 提交/撤销/候补确认/调剂操作后，必须能查到：
  - `application_status_histories`
  - `audit_logs`

### 6. 不算完成的情况

- 只做了页面，没有真实调接口
- 通过手工改库制造补件、撤销、候补确认结果
- 详情页展示字段与接口真实返回不一致
- 对未实现接口自行 mock 成“已完成”

## 三、B 模块验收（国内审核）

### 1. 页面范围

- `DomesticReviewListPage`
- `DomesticReviewDetailPage`

### 2. 必须完成

- 国内审核详情页可通过真实申请详情接口展示申请信息
- 能认领待审核申请
- 能提交三类审核结果：
  - `PASS`
  - `SUPPLEMENT_REQUIRED`
  - `REJECT`
- 国内审核列表页如果后端接口未实现，只允许保留占位说明，不得伪造列表数据接口

### 3. 必须真实联调的接口

- `POST /api/auth/login`
- `POST /api/auth/change-password`
- `GET /api/auth/me`
- `GET /api/applications/{id}`
- `POST /api/domesticreviews/{id}/claim`
- `POST /api/domesticreviews/{id}/submit`

### 4. 必须通过的固定场景

- 从一条 `SUBMITTED` 申请执行 `claim` 成功，状态进入 `DOMESTIC_REVIEWING`
- 提交 `PASS` 后，状态进入 `SCHOOL_REVIEWING`
- 提交 `SUPPLEMENT_REQUIRED` 后，状态进入 `DOMESTIC_SUPPLEMENT`
- 提交 `REJECT` 后，状态进入 `DOMESTIC_REJECTED`

### 5. 数据库验收点

- `domestic_reviews` 有对应审核记录
- `applications.current_status` 与审核结果一致
- `application_status_histories` 有状态流转记录
- `audit_logs` 有认领和提交记录

### 6. 不算完成的情况

- 列表页接了不存在的 `/api/domesticreviews/pending`
- 认领和提交没有写入历史或审计日志
- 审核结论只在前端显示，数据库无真实变更

## 四、你模块验收（核心负责人）

### 1. 页面范围

- `LoginPage`
- `DashboardPage`
- `SchoolReviewListPage`
- `SchoolReviewDetailPage`
- `WaitlistManagePage`
- `BatchesPage`
- `SchoolsMajorsPage`
- `QuotasPage`
- `UsersPage`
- `AuditLogsPage`

### 2. 必须完成

- 登录页完成首次改密闭环
- 工作台保留占位且不接假接口
- 学校审核详情页能提交四类学校审核结果：
  - `RESERVE`
  - `WAITLIST`
  - `REJECT`
  - `SUGGEST_ADJUSTMENT`
- 候补管理页能查询、推进、失效候补
- 批次管理页能新增、修改、更新批次状态
- 学校与专业配置页能完成学校和专业配置维护
- 配额管理页能查看并调整学校/专业名额
- 用户管理页能查看、创建、修改、启停用户
- 日志查询页能查审计日志和状态历史
- 学校审核列表页如果后端接口未实现，只允许占位说明

### 3. 必须真实联调的接口

- `POST /api/auth/login`
- `POST /api/auth/change-password`
- `GET /api/auth/me`
- `GET /api/applications/{id}`
- `POST /api/school-reviews/{id}/submit`
- `GET /api/waitlists/{applicationId}`
- `POST /api/waitlists/{applicationId}/promote`
- `POST /api/waitlists/{applicationId}/invalidate`
- `GET /api/batches`
- `POST /api/batches`
- `PUT /api/batches/{id}`
- `POST /api/batches/{id}/status`
- `GET /api/schools`
- `POST /api/schools`
- `PUT /api/schools/{schoolCode}`
- `POST /api/schools/{schoolCode}/status`
- `GET /api/majors`
- `POST /api/majors`
- `PUT /api/majors/{majorCode}`
- `POST /api/majors/{majorCode}/status`
- `GET /api/quotas`
- `GET /api/quotas/adjustments`
- `POST /api/quotas/schools/{id}/adjust`
- `POST /api/quotas/majors/{id}/adjust`
- `GET /api/users`
- `POST /api/users`
- `PUT /api/users/{id}`
- `POST /api/users/{id}/status`
- `GET /api/audit-logs`
- `GET /api/audit-logs/status-histories`

### 4. 必须通过的固定场景

- `127` 或 `137`：候补详情查询、推进成功
- `128`：候补确认后状态链路正确
- `129` 或 `138`：预录取终态展示正确
- `130` 或 `144`：学校建议调剂结果能正确触发调剂链路
- 批次发布时，学校总名额与专业名额不一致会被阻止

### 5. 数据库验收点

- 学校审核提交后，必须联动检查：
  - `school_reviews`
  - `applications`
  - `application_status_histories`
  - `audit_logs`
- 候补推进/失效后，必须联动检查：
  - `waitlist_records`
  - `applications`
  - `school_quotas`
  - `major_quotas`
  - `application_status_histories`
  - `audit_logs`
- 配额调整后，必须检查：
  - `school_quotas` 或 `major_quotas`
  - `audit_logs`
- 用户启停后，必须检查：
  - `users`
  - `audit_logs`

### 6. 不算完成的情况

- 学校审核列表页接了不存在的 `/api/school-reviews/pending`
- 工作台接了不存在的 `/api/dashboard/**`
- 配额调整只改页面展示，没有真实落库
- 候补操作后没有同步写历史和日志

## 五、统一通过标准

- 每个负责人至少完成自己范围内全部 P0 页面。
- 每个真实联调页面都必须有对应接口成功调用记录。
- 每条核心业务动作都必须能在数据库中查到：
  - `application_status_histories`
  - `audit_logs`
- 占位页必须明确写“当前后端未实现”，不得伪装成真实能力。
- 验收结论只能是：
  - 通过
  - 未通过

## 六、统一未通过条件

- 调用了接口文档中未实现的接口
- 修改了不归属自己的页面、公共文件、后端模块或数据库表
- 通过手工改库制造验收结果
- 页面看起来完成，但无法复现实操流程
